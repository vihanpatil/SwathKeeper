description: Run the FieldGuard tiger-team standup to open a work session
---

Run a tight, 10-minute-max tiger-team standup for the FieldGuard project. Do NOT let this become
theater — keep it short and decision-oriented. Follow these steps in order:

1. **Product Lead sets the goal.** Adopt the `product-lead` lens (read `docs/ROADMAP.md` and the
   product-lead's memory). State in ONE sentence the single goal for this work session and name
   the one outcome that would make the session a failure. Confirm it ladders up to a roadmap
   milestone and the ~7-8 week deadline.

2. **Tech Lead flags architecture risk.** Adopt the `tech-lead` lens. In 1-3 bullets, call out any
   architecture or interface risk relevant to today's goal (check `docs/DECISIONS.md` and open
   interface questions). If there's none, say "no architecture risk for this goal" — don't invent one.

3. **Everyone else stays silent unless blocking.** Only surface a note from `perception-ml-engineer`,
   `robotics-sim-engineer`, `flight-software-engineer`, `devops-reliability-engineer`,
   `qa-safety-reviewer`, or `gtm-narrative-lead` if that role has a genuine blocker or dependency on
   today's goal. No status theater.

4. **Output**: a 5-8 line standup summary — Goal, Failure condition, Architecture risk, Blockers (if
   any), and the concrete first action. Then ask which role(s) I want to drive the work, and
   proceed.
